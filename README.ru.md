# goodix-5503-fingerprint-login

Вход по отпечатку на Linux для сенсора Goodix `27c6:5503`.

## Статус

Рабочий прототип. `sudo` и разблокировка экрана работают по отпечатку. Первый вход
через дисплей-менеджер не работает, и пароль всегда доступен как запасной вариант,
поэтому неудачное считывание или остановленный демон заблокировать вход не могут.

| Сценарий | Работает | Причина |
|---|---|---|
| `sudo` в терминале | да | сессия пользователя и демон уже запущены |
| Разблокировка экрана через PAM, например hyprlock | да | сессия активна, демон держит устройство |
| Первый вход на экране дисплей-менеджера | нет, пароль | демон стартует после входа, на экране входа сессии ещё нет |

На небольшом тестовом наборе: FAR близко к нулю, чужие касания дали ноль
соответствий. Это результат на этом наборе, а не общая оценка точности.

## Важно: нужна своя DLL

`GoodixEngineAdapter.dll` это проприетарная библиотека алгоритма Goodix. В
репозитории её нет. Её нужно взять из установленного Windows-драйвера Goodix для
конкретного ноутбука и скопировать в:

```
re/GoodixEngineAdapter.dll
```

## Как это работает

```
Захват по USB и TLS-PSK, Python
      -> fpsvc под Wine, грузит GoodixEngineAdapter.dll
      -> число соответствий, читается через INT3 брейкпоинт
      -> демон fpd, Python, от имени пользователя
      -> fp_pam.py, root-хелпер
      -> PAM
```

Вендорный экспорт `identifyImage` всегда возвращает отрицательный скор -100, пока
не воспроизведён его полный адаптивный цикл регистрации и зрелости, а вызвать это
напрямую непрактично. Но различение считается раньше: число совпавших соответствий
признаков у инструкции `cmp $0x4,%edi` в `FUN_18009f4a0`. Свой отпечаток даёт много
соответствий, чужой даёт ноль, ещё до этапов подсчёта скора и проверки зрелости.
Демон читает это
число брейкпоинтом и использует напрямую как решение о совпадении. Детали и
декомпиляции находятся в [re/research/](re/research/).

## Требования

- Сенсор Goodix `27c6:5503` с доступом на запись к его USB-узлу через правило udev
  или группу.
- Python 3.11+ и зависимости из requirements.txt: pyusb, numpy, scipy, pillow.
- Wine, проверено на 11.x, для запуска матчера.
- mingw-w64, компилятор `x86_64-w64-mingw32-gcc`, для сборки `fpsvc.exe` и stub DLL.
- Своя `GoodixEngineAdapter.dll`.
- Ghidra и pyghidra нужны только для исследовательских скриптов.

## Установка

### 1. Клонирование

```bash
git clone https://github.com/H4ZEIeaz/goodix-5503-fingerprint-login.git
cd goodix-5503-fingerprint-login
```

### 2. Окружение Python

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

### 3. Добавить DLL

Нужно скопировать свою `GoodixEngineAdapter.dll` в `re/`, как указано выше.

### 4. Сборка матчера и stub DLL

```bash
cd re
x86_64-w64-mingw32-gcc -shared stub.c stub.def -o api-ms-win-core-debug-minidump-l1-1-0.dll
x86_64-w64-mingw32-gcc fpsvc.c -o fpsvc.exe
cd ..
```

### 5. Калибровка

Сенсор нужно держать пустым. На выходе получаются `re/frames/base.raw` и
`re/frames/calidata.blob`.

```bash
./.venv/bin/python calibrate.py
```

### 6. Регистрация отпечатка

Около 15 касаний, покрыть всю площадку.

```bash
./.venv/bin/python fp_enroll.py thumb
```

### 7. Проверка

```bash
./.venv/bin/python fp_verify.py thumb
```

## Демон

Демон держит устройство и матчер, поэтому каждая проверка это одно касание вместо
примерно 5 с на запуск Wine. Ставится как user-сервис. Если репозиторий лежит не в
`~/goodix-5503-fingerprint-login`, сначала нужно поправить два пути в `fpd.service`.
Юнит запускает шаблон `thumb` с порогом 3. При другом имени шаблона нужно поправить
`ExecStart`.

```bash
mkdir -p ~/.config/systemd/user
cp fpd.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now fpd.service
```

Проверка работоспособности:

```bash
python3 -c "import socket,os; s=socket.socket(socket.AF_UNIX); s.connect(os.path.expandvars('$XDG_RUNTIME_DIR/fpd.sock')); s.send(b'PING\n'); print(s.recv(16))"
```

### Протокол сокета

Демон слушает `$XDG_RUNTIME_DIR/fpd.sock`, один запрос на соединение:

| Запрос | Ответ |
|---|---|
| `PING` | `OK` |
| `AUTH` | `ACCEPT corr=N`, `REJECT ...` или `ERR ...` |
| `AUTH <timeout> <retries>` | то же, timeout от 1 до 30 с, retries от 1 до 5 |

## PAM

PAM нужно править аккуратно. Следует держать открытым root-шелл и сделать резервную
копию, например `cp /etc/pam.d/sudo /etc/pam.d/sudo.bak`, а также знать путь в
текстовую консоль по Ctrl+Alt+F2. Схема `sufficient` плюс пароль заблокировать
пользователя не может, но ошибочная строка в стеке `auth` может, поэтому проверять
нужно во втором терминале.

`fp_pam.py` это небольшой root-хелпер только на stdlib. Он спрашивает демон через
сокет и выходит с кодом 0 для приёма или 1 для перехода к паролю. Эту строку нужно
добавить первой строкой auth, выше всех остальных строк auth и include, в
`/etc/pam.d/sudo` и при желании в `/etc/pam.d/hyprlock`:

```
auth sufficient pam_exec.so quiet /ABSOLUTE/PATH/TO/fp_pam.py
```

Стоящая первой как `sufficient`, она делает совпадение отпечатка достаточным, а
любая неудача проваливается к модулям пароля ниже. Затем проверить во втором
терминале:

```bash
sudo -k; sudo echo ok
```

### Опции

| Опция | Значение |
|---|---|
| `--timeout S` | секунды ожидания пальца на одну попытку |
| `--retries N` | число попыток до отката на пароль, по умолчанию 3 |
| код выхода 0 | отпечаток принят |
| код выхода 1 | отказ или недоступно, дальше запрос пароля |

Целевая учётная запись берётся из `$PAM_USER`.

## Безопасность и приватность

- Шаблоны, захваченные кадры и DLL никогда не коммитятся. Они перечислены в
  `.gitignore`. Шаблон это биометрические данные.
- Калибровка привязана к устройству и содержит эталонный кадр пустого сенсора, без
  отпечатка. Она генерируется `calibrate.py` и игнорируется git.
- Dual boot: загрузка Windows заставляет его драйвер Goodix заново записать PSK
  устройства, и захват на Linux падает, пока community PSK не восстановлен. Код
  захвата делает это автоматически одной записью в NVM устройства, что обратимо.
  Если на устройстве уже стоит community PSK, ничего не записывается. Иначе
  записывается тот же community PSK в white-box виде.
- Константы PSK в `capture_bio_5503.py` это публичный community PSK, не секреты.

## Справка

Переменные окружения:

| Переменная | По умолчанию | Действие |
|---|---|---|
| `FP_THRESHOLD` | 3 | минимальное число соответствий для приёма |
| `FP_TEMPLATE` | template.bin | путь к шаблону, относительно `re/` |
| `GOODIX_CLEAR_ONLY` | не задано | остановиться после калибровочных кадров, без пальца |
| `GOODIX_BG_FRAMES` | 10 | кадры пустого сенсора для базовой линии |
| `GOODIX_FP_FRAMES` | 12 | кадры пальца в серии |

Детект пальца использует порог 150 на пиксель и требует 1500 отличающихся пикселей.

Команды `fpsvc.exe`, запускаются из `re/` под Wine:

| Команда | Действие |
|---|---|
| `fpsvc enroll <dir>` | регистрация всех `<dir>/*.raw` в шаблон |
| `fpsvc verify <probe.raw>` | сравнение пробы с шаблоном |
| `fpsvc serve` | постоянный режим, читает сырые кадры из stdin |

Строки вывода имеют вид `RESULT corr=N verdict=ACCEPT` или `verdict=REJECT`.

## Ограничения

- Проприетарная вендорная DLL нужна во время работы через Wine. Это мост, а не
  чистый драйвер.
- Нет отпечатка на экране входа дисплей-менеджера. Демон работает от пользователя и
  стартует после входа. `sudo` и разблокировка экрана работают.
- Тестирование на уровне прототипа. Откат на пароль это страховка.

## Дорожная карта

Переиспользуемые части это находка про число соответствий и байт-точный оракул для
5503, так как тестовая программа под Wine воспроизводит DLL побайтово. Именно это
использовал [goodix53x5-libfprint](https://github.com/seaweeduk/goodix53x5-libfprint),
чтобы сделать нативный порт Milan для других сенсоров Goodix. Нативный порт 5503,
без DLL во время работы и интегрированный с libfprint, это чистая цель. Этот репозиторий
точка опоры, см. [re/research/](re/research/).
